# A57
【ルシフォン#e】
結論：その手の「ファイル構成＋ドキュメント整理」だけなら、たいてい refactor までは行かない。だいたい docs か chore で十分。

docs:
Markdownの追加/修正、構成整理、リンク修正、命名整理（＝“内容はドキュメント範囲”）
例：docs: reorganize planning docs / docs(t-hunt): restructure docs

chore:
リポジトリ運用の整備（ディレクトリ移動、.gitignore、設定ファイル、運用フォルダの整理）
例：chore: reorganize repo layout / chore: update .gitignore and move docs

refactor:
“コード”の内部整理（動作は変えないが、実装を組み替えた）に使う。
Markdown整理だけなら refactor は基本使わない（使うなら chore に寄せたほうが誤解が少ない）。

今の君のやつは、素直にいくなら docs（中身が主）、構成移動やignore整備が主なら chore が綺麗。
